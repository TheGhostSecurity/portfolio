Selected work

SomaCloud

Cybersecurity Sandbox Platform · Final-Year Project

Source
  • Python
  • Django 6
  • Docker Swarm
  • ttyd
  • mTLS

A self-hosted training platform that provisions isolated Kali Linux sandboxes on remote Docker nodes, giving students a real terminal in the browser and purpose-built vulnerable services to attack — no local setup required.

What I built

  • 59-lab curriculum across 9 attack phases, each lab bundling theory, walkthroughs, challenge questions, container definitions and flag submission.
  • Multi-node scheduler that scores candidate nodes by resource fit and rejects placements that would over-commit CPU, RAM or the port range.
  • Self-hosted CA + mutual TLS between app server and workers, with zero-touch provisioning: registering a host installs Docker, issues a certificate and joins it to the Swarm.
  • Encrypted scriptable backups so the whole platform restores onto new infrastructure in a single command.
  • Instructor analytics — per-student and cohort charts, activity timelines, flag review and PDF export.

ShamsQuiz

Live classroom quiz game · with mobile API

Source API docs
  • Django
  • Channels / WebSockets
  • Redis
  • DRF + JWT
  • Apache2

A real-time quiz platform where teachers host a session and students join with a six-character code — no accounts required. Scores update live for everyone in the room.

What I built

  • Real-time state sync over WebSockets (Django Channels + Redis) driving a live top-5 podium and full-screen scoreboard.
  • Time-decaying scoring — 1,000 points per question, worth less the slower you answer — with a reusable question bank.
  • Documented REST + WebSocket API (358-line spec) with JWT auth and CORS policy, so the game is playable from a mobile client.
  • Reporting & admin — per-session PDF reports, score charts, and a panel for users, sessions and activity logs.

F.R.I.D.A.Y

Permission-gated local AI agent

Source
  • FastAPI
  • Ollama
  • Local LLM
  • pytest

A local AI agent whose model has no direct filesystem access. Every tool call passes through a gateway that enforces an allow / ask / deny permission policy before anything touches disk.

What I built

  • The permission boundary — one-time approvals bind to an exact action and resource, so an approval cannot be reused for a broader operation later.
  • Traversal & symlink hardening — paths are resolved and checked for containment against allowed roots, closing off symlink escapes.
  • 14 automated tests covering permission boundaries, filesystem policy and CLI behaviour.
